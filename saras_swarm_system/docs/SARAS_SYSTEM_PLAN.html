01 / NORTH STAR

What we are building

SARAS is not only a drone. It is a simulation-first autonomy platform where one physical drone can later operate as one node inside a larger simulated swarm.

System promise: multiple drones divide a disaster zone, search without unnecessary overlap, detect and locate victims, survive node failures, and give an operator explainable rescue priorities through one shared architecture.
Working now

Simulation baseline

Configurable drones, sectors, victims, battery drain, detection, auction allocation, failure reassignment, rescue ranking, and report generation.

Working now

Operator dashboard

Leaflet map, drone markers, victim markers, sector overlays, roster, telemetry refresh, rescue queue, and agent recommendation.

Next focus

System hardening

Backend state, repeatable evaluation, policy interfaces, real telemetry schema, and physical-drone compatibility.

02 / SYSTEM DESIGN

Architecture that scales

Each layer has a clear responsibility. Simulation and hardware share data contracts, while the dashboard remains an observer and operator surface rather than a mission controller.

MissionTerrain, sectors, victims, hazards, rescue points
Drone nodesSimulated PX4 or physical Pixhawk/MAVLink node
PerceptionYOLO edge inference and normalized detections
CoordinationAllocation, coverage, heartbeat, reassignment
BackendFastAPI state, events, commands, persistence
OperatorLeaflet dashboard, agents, RAG, human approval

Non-negotiable boundaries

  • Flight control stays in PX4; SARAS sends mission-level commands.
  • Coordination logic must not depend on a browser or UI state.
  • Generative AI cannot silently issue safety-critical flight commands.
  • Simulation uses the same normalized telemetry/detection shape as hardware.

  • ARCHITECTURE.md — current architecture

04 / EXECUTION ROADMAP

Build in the right order

Every phase ends with a demonstrable result. Do not start hardware integration or RL research before the baseline produces trustworthy measurements.

00
Alignment

Freeze scope and contracts

  • Confirm MVP: 3–5 simulated drones, one physical-drone path, sectors, victims, failure recovery, dashboard, rescue support, and evaluation.
  • Freeze telemetry, detection, command, report, and coordinate schemas.
  • Record deferred items: mesh networking, 10+ swarm scaling, LiDAR, thermal camera, cloud deployment.
Exit: both members can produce and consume the same sample telemetry and detection messages.
01
Foundation

Make simulation research-grade

  • Separate mission generation, drone state, allocation policy, simulation loop, event log, and metrics.
  • Add deterministic seeds, scenario files, configurable drone count, and batch execution.
  • Implement victim locking, low-battery return, coordinator degradation, and clean reassignment semantics.
Exit: repeated runs are reproducible and the same code runs 1, 3, and 5 drones.
02
Measure

Build the evaluation harness

  • Record coverage completion time, detection latency, redundant-search rate, failure recovery time, mission completion, and response distance.
  • Run scenario batches with fixed seeds and export JSON/CSV experiment results.
  • Produce baseline plots and a comparison table suitable for Paper 2.
Exit: auction baseline results are defensible and repeatable before learned policy work begins.
03
Learn

Add configurable swarm intelligence

  • Introduce an allocator interface: auction, heuristic, and learned policies.
  • Train/evaluate a lightweight policy using the same observation/action/reward contract.
  • Compare learned allocation against auction baseline under normal and failure scenarios.
Exit: learned policy shows measurable improvement or a documented trade-off, not only a qualitative demo.
04
Integrate

Move from report polling to live backend state

  • Add FastAPI endpoints for mission, drones, sectors, detections, recommendations, and event history.
  • Use WebSocket or Server-Sent Events for state updates; keep JSON export for experiments.
  • Retain Leaflet but replace the static-file source with the backend adapter.
Exit: the dashboard can observe a running simulation without reading internal Python files.
05
Intelligence

Add bounded agentic AI and RAG

  • Keep rescue prioritization deterministic and explainable.
  • Add retrieval with source citations, relevance checks, and an explicit “insufficient evidence” response.
  • Evaluate recommendation consistency and retrieval relevance with a small fixed test set.
Exit: operator receives useful, source-grounded advice without the model becoming an uncontrolled flight planner.
06
Hardware

Bring one physical drone into the same swarm

  • Connect Pixhawk/PX4 and Raspberry Pi through the agreed MAVSDK/MAVLink adapter.
  • Stream real telemetry and edge detections using the same schemas as SITL.
  • Run mixed mode: one physical node plus simulated nodes, with safe manual override and geofencing.
Exit: the physical drone appears as a normal swarm node and does not require a separate coordination implementation.
07
Publish

Freeze the demo and papers

  • Capture simulation-only and mixed-mode demo videos/screenshots.
  • Freeze experiment configurations and archive result artifacts.
  • Complete separate Edge ML and Swarm ML/Agentic AI papers with explicit interface references.
Exit: every success criterion is demonstrated, measured, or explicitly documented as deferred.
